## はじめに

請求書・見積書・納品書・領収書・退職届・履歴書など12種類のビジネス書類を、登録なしでブラウザから作ってPDFにできる **Free BizDoc** というサービスを個人で作って運用しています。

https://free-bizdocs.com

「無料で使えて、データをサーバーに置かない書類ツールが欲しい」という自分の需要から始めて、サーバー費用ほぼゼロで回る構成にしました。この記事では採用した構成と、作ってみて分かったハマりどころをまとめます。

## 構成

全部 Cloudflare に寄せました。

| 役割 | 使ったもの |
|---|---|
| 静的ページ・ツール本体 | Cloudflare Pages（素のHTML + JS、フレームワークなし） |
| API | Pages Functions |
| DB | D1（SQLite） |
| 認証 | 自前（メール+パスワード / PBKDF2）＋ Google OAuth |
| 課金 | Stripe Payment Links + Customer Portal |
| メール | Resend |
| 定期ジョブ | Workers Cron（X への自動投稿） |

月額の固定費はドメイン代だけです。Pages / Functions / D1 はすべて無料枠の範囲で動いています。

### フレームワークを使わなかった理由

書類ツールは「フォームに入力 → プレビュー → PDF」の一本道なので、Reactや Next.js を入れるほどの状態管理がありません。素のJSにした結果、

- ビルドなし。`wrangler pages deploy .` で即反映
- 1ページあたりの JS が小さく、スマホでも軽い
- SEO 的に初期HTMLに全部入っている

という素直なメリットがありました。12種類の書類で共通する処理（明細の追加削除、合計計算、PDF生成、保存）は `tool.js` 1ファイルにまとめ、各書類ページは HTML テンプレートの差分だけ持つ形です。

## ハマりどころ

### 1. D1 はローカルとリモートで別物

`wrangler d1 execute` はデフォルトでローカルの SQLite を叩きます。本番に流すには `--remote` が必要で、これを忘れて「マイグレーション流したのにテーブルがない」を一度やりました。本番と開発でスキーマがズレないよう、マイグレーションは必ずファイルにして両方に流す運用にしています。

### 2. Pages の `_headers` はワイルドカードの書き方が独特

静的アセットに長めのキャッシュを付けたくて `*.css` と書いたら効きませんでした。Pages の `_headers` は

```
/*.css
  Cache-Control: public, max-age=31536000
```

のように **パス全体をマッチさせる** 形で書く必要があります。先頭の `/` を忘れると無視されます。

### 3. 共有リンクをサーバーに保存しない設計

「作った請求書をURLで相手に送りたい」という要望に対して、書類データをサーバーに保存せず、**URL のハッシュ部分（`#s=...`）に base64 で載せる** 方式にしました。

```js
const payload = btoa(unescape(encodeURIComponent(JSON.stringify(doc))));
location.href = `/invoice#s=${payload}`;
```

ハッシュはサーバーに送信されないので、取引先名や金額がログに残りません。受け取った側は読み取り専用ビューで開き、PDF ダウンロードだけできます。デメリットは URL が長くなること。ロゴ画像や印影は含めないルールにして現実的な長さに収めています。

### 4. 無料枠での保存上限と課金の分岐

ログインユーザーは書類を保存できますが、無料は5件まで。6件目で API が 403 を返し、フロントでアップセルのモーダルを出す、というシンプルな分岐です。

課金は Stripe の Payment Links を使い、自前で Checkout を実装していません。Customer Portal も有効にして解約・カード変更はユーザー自身で完結するようにしました。個人開発で「解約したい」というメール対応をしないで済むのはかなり大きいです。

### 5. 認証は PBKDF2 + 署名付きCookie

Workers では `bcrypt` のネイティブ依存が使えないので、Web Crypto の PBKDF2 でハッシュ化しています。セッションは HMAC 署名付きトークンを Cookie に入れ、D1 にセッションテーブルは持ちません。Google ログインは OAuth の認可コードフローを Pages Functions で直接書きました（ライブラリなし、200行くらい）。

### 6. X への自動投稿は従量課金

集客用に X（旧Twitter）へ1日3回の自動投稿を Workers Cron で回しています。2026年現在、X API は無料枠がなく **投稿1件ごとの従量課金** です。しかもリンク付き投稿は単価が高いので、本文にはリンクを入れず、プロフィール欄のURLだけに誘導を絞りました。OAuth 1.0a の署名を Workers で自前実装する必要があり、ここは地味に手間でした。

## 運用して分かったこと

- **「登録不要」はコンバージョンに効く**。アクセスの大半はログインせずに1枚作って帰る人で、そこから「保存したい」で登録に進む流れが自然でした
- **書類間の変換が一番使われる機能**。見積→請求→納品→領収を同じ明細で切り替える機能は、後から足したのに利用率がトップです
- **Cloudflare 完結は個人開発に向いている**。Pages / Functions / D1 / Cron / Secrets が1つのダッシュボードにあるので、インフラを考える時間がほぼ消えます

## まとめ

- 素のHTML + Pages Functions + D1 で、固定費ゼロの書類作成SaaSが作れる
- 共有はURLハッシュに載せてサーバーレスにすると、プライバシーと運用コストの両方が軽くなる
- 課金・解約は Stripe の Payment Links と Customer Portal に丸投げする
